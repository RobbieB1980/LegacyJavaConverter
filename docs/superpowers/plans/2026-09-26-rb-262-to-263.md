# RB 26.2 to 26.3 Converter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Create a standalone, conservative RB 26.2→26.3 converter target while leaving the existing legacy→26.2 converter unchanged.

**Architecture:** Add a target-specific package under `targets/rb-26.2-to-26.3`. It reuses the existing PowerShell build/evidence conventions but owns its Minecraft/NeoForge 26.3 metadata, data/resource migration rules, validation gates, and repair handoff. The current converter remains the supported legacy→26.2 product.

**Tech Stack:** PowerShell 7/5.1-compatible scripts, JSON metadata, executable tests already used by the repository, NeoForge 26.2→26.3 migration primer evidence.

**Spec:** `docs/ARCHITECTURE.md`, `docs/SUPPORTED-VERSIONS.md`, and the official NeoForge 26.2→26.3 primer.

## Global Constraints

- Existing legacy converter target remains NeoForge 26.2.
- New target accepts only NeoForge 26.2 input and emits NeoForge 26.3 output.
- Original input is never modified; conversion writes to a separate output directory.
- Data/resource/worldgen rewrites must be deterministic and idempotent.
- Client/rendering changes are reported for repair; they are not guessed by regex.
- Build success and runtime/content validation remain separate gates.
- Exact source evidence and target metadata must be recorded in the conversion manifest.

## Review Focus

- Reject non-26.2 input rather than silently retargeting it.
- Reject an output directory equal to the input directory.
- Preserve unknown JSON fields while applying only known 26.3 changes.
- Refuse ambiguous number-provider and renderer/API changes instead of inventing edits.
- Keep the existing 26.2 converter files and behavior unchanged.
